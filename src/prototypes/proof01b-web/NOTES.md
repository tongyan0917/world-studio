# Proof 01B Visual Prototype — Learning Notes

> THROWAWAY feedback record. Judge whether the world, history, and causal boundary are understandable—not whether the page is polished.

## Question

Which visual structure best communicates both sides of Proof 01B?

1. the town is a changing world with people, organizations, places, infrastructure, events, and history; and
2. a possible change becomes World history only after its causal and authority conditions are satisfied.

## Implementation learning already captured

These are properties of the comparison setup, not a user verdict about the winning UI:

- World-language and technical protocol-language can coexist if World state is primary and artifact identities remain available in a secondary audit surface.
- Holding all three variants over one server-owned session makes the comparison fair: the same action, candidate, and Receipt lineage are being explained three ways.
- Multiple successful phases can occur at the same `T1`; the UI must distinguish “history gained another causal consequence” from “World Time advanced.”
- zero closure, `B + 1` incomplete, a dormant proposal, and a failed publication barrier need visibly different explanations even though all can leave the committed Base unchanged.
- A browser projection can preserve the prototype's authority boundary when it sends actions rather than candidate state and never receives the opaque authority anchor.

## Browser QA — 2026-08-10

- A, B, and C rendered over the same live session with distinct information hierarchies and no browser console errors.
- One full publication changed the visible authority from Base v0 to v1, added the road closure to history, and exposed the council-alert candidate without presenting it as committed fact.
- The zero-after-two fixture ended as `empty-closed` with no enabled primary action and no false “current” phase-rail step.
- The non-empty fixture ended at the `B + 1` Budget gate with Base v2 retained and no false downstream step.
- An armed publication failure left Base v0 and depth 0 unchanged, kept the candidate retryable, and the next publication succeeded as Base v1.
- The server rejected a stale revision with `409` and an unknown action with `400`; the existing Proof 01A routes remained available.

This is implementation and QA evidence only. It does not choose a winning visual direction; that verdict belongs to the person evaluating the page.
